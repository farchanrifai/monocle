# Codebase Reliability Audit — 2026-09-19

Branch: `gpt-review`  
Base: `gemini` at `03701e9`  
Scope: app, widgets, App Intents, persistence, backup/restore, CSV, recurring bills, Live Activities, unit tests and UI tests.

## Outcome

The audit found and fixed several cross-feature integrity failures. The highest-risk issue was that a user-facing "full backup" and destructive-operation safety backups could omit workspace data when only one card existed. The daily entry, card-switching, CSV, widget, shortcuts, bills and spending-session paths now share the correct card context and retain failed drafts.

## Applied fixes

### Data safety

- Full backup, safety backup and rollback snapshots now always use `WorkspaceBackup`, preserving bills, per-card drafts, stacks, preferences and card artwork in addition to ledger data.
- Workspace validation rejects cross-card expenses, budgets and drafts; invalid occurrence references and aggregate integer overflow are rejected before restore.
- Workspace restore reopens the restored active card and its draft, then invalidates cached ledger/widget data.
- Clearing transactions marks linked bill occurrences skipped so automatic reconciliation cannot recreate deleted spending.

### Cross-feature connections

- Card selection is validated and atomic from the model's point of view: current draft is saved, target draft is loaded, then card state and caches change.
- Entry deep links only accept a category active on the target card.
- Quick Capture widget links include the active card.
- CSV all-card export loads categories from every card; import category choices follow the selected target card.
- Shortcut prompt order is deduplicated, and category selection is revalidated after card resolution.
- Spending sessions are scoped to their starting card, reject overflow, avoid edit double-counting and include shortcut-created expenses.
- Settings rename and category context follow the selected card rather than stale single-card settings.

### Daily-flow reliability

- Failed expense saves keep the entry sheet and draft open so the user can correct the error.
- Redundant navigation stacks were removed from pushed/sheet content to restore predictable dismissal and back behavior.
- Six stale or environment-bound UI tests were repaired: card-creation labels, category screenshot storage, native tab-bar expectations, settings scrolling and failed-save behavior.
- Project metadata and README version references now match 0.7.20 build 83.

## Stress and regression coverage

- Added regression checks for complete safety backups, cross-card backup rejection, recurring-bill clearing, per-card draft swapping, all-card CSV categories, shortcut order/category resolution and card-scoped spending sessions.
- Added a daily-ledger stress check covering 750 inserts, 30 updates, 15 deletes and 150 card switches while verifying per-card counts, totals and identity isolation.
- Existing UI stress coverage rapidly opens/closes card flows and exercises dense-category and responsive-layout paths.

## Remaining risks

- Card customization and several category/bill UI actions still use best-effort writes. A mid-save storage failure can report poorly or leave a partially applied multi-step customization. Fix this only with a repository transaction boundary; adding view-level alerts would not make the operation atomic.
- Core Data writes and cross-card aggregation run on the main actor. The new hundreds-of-record stress check protects correctness, but not frame-time or memory targets near the 10,000-record import ceiling.
- Simulator automation cannot prove notification delivery, Face ID prompts, widget/Live Activity launch, SideStore persistence, VoiceOver order or animation feel on physical 60/120 Hz devices.
- XCTest recorded four non-fatal runtime warnings: two SwiftUI frame warnings while focusing text fields and two UIKit hierarchy warnings from the system context-menu presentation. No assertion or layout check failed; treat these as device-validation watch items rather than adding speculative layout code.
