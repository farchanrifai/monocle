# Monocle audit — 0.6.18 (54)

Scope: application state, Core Data persistence, backup/recovery, CSV, bills/notifications, analytics, photo artwork, SwiftUI interactions, accessibility-related motion, test infrastructure, and SideStore packaging. The visual layout, typography, artwork designs, and card spring constants are preserved.

## Changes and expected impact

| Area | Defect or cost | Improvement | Expected impact |
| --- | --- | --- | --- |
| Bills | Upcoming automatic bills already existed as pending, so reconciliation skipped them forever | Promote due pending occurrences while preserving occurrence identity | Automatic bills record once when reconciliation runs |
| Bill confirmation | Repeating confirmation created a second expense; skip could overwrite recorded state | Reject already resolved occurrences | Prevent duplicate spending and inconsistent status |
| Transactions | CSV and bill writes saved each row separately | Repository transaction boundary, rollback on error, single outer commit | Prevent partially imported files and orphan bill expenses; fewer disk commits |
| Book isolation | Occurrence deletion ignored the book argument | Scope deletion through the owning rule and book | Prevent deleting another book's occurrence |
| Categories | Deletion checked expenses but not bill rules | Reject deletion of a bill's category | Keep future bill recording valid |
| Notifications | Editing reminders ignored existing pending occurrences; asynchronous adds could outlive cancellation | Refresh pending reminders after rule edits and serialize add/cancel replacement | Avoid stale or resurrected reminders |
| Loading | Failed scoped reads fell back to a different/default book | Load a complete scoped snapshot before publishing it; restore selection on failure | Errors remain visible instead of displaying mismatched data |
| Backup preview | In-memory validation imported artwork into live storage | Disable artwork import for preview | Preview no longer changes current card photos |
| Workspace restore | Only the first book's draft was restored/recovered | Save every draft to its book-specific file, including empty drafts | Preserve all drafts and remove stale drafts during restore |
| Backup snapshots | Current draft was assigned using settings rather than its book ID | Use the draft's actual owner | Correct multi-book backups |
| Recovery | Legacy operations could journal only one book of a larger workspace | Journal the full workspace when multiple books exist | Preserve other books during rollback |
| Backup validation | Artwork filenames and orphan bill occurrences were unchecked | Validate filenames, ownership, rule links, dates, and globally duplicated expense IDs | Reject inconsistent backups before restore |
| Photos | Decode/resize ran on the main actor; newer selections could lose a race | Background preparation, cancellation, immutable filenames, abandoned-file cleanup | Reduce photo-picker stalls and protect the saved artwork on cancellation |
| Memory | Image cache limited item count but not decoded bytes | Add a 48 MiB cache cost limit | Bound the intended decoded-artwork cache budget; NSCache may evict earlier |
| Card motion | Two handlers animated opening, duplicate dismissal recognizers, and stale close completion | Single open/dismiss ownership, directional release guards, and guarded completion after spring removal | More predictable interrupted/reversed transitions |
| History rendering | Every transaction row was eagerly built | LazyVStack with existing spacing and backgrounds | Reduce initial layout work for long histories |
| Derived state | Observable caches were mutated during view reads; stack edits/reload could retain stale activities | Ignore private memoization in observation and invalidate it on changes | Reduce unnecessary view updates and stale history |
| Currency | A NumberFormatter was created per label | Native Decimal format styles | Allow Foundation to reuse formatting infrastructure |
| Cycle queries | Calendar/budget period was reconstructed for each expense | Compute the cycle once per filter | Reduce repeated calendar work |
| Analytics | Exclusive next-cycle boundary was treated as inclusive; one-day target used two days | Correct inclusive display boundary and day count | Correct cycle totals and target pacing |
| Analytics scope | Cross-book chart ignored the selected date horizon | Filter book distributions by that horizon | Consistent chart comparisons |
| CSV | Arbitrary text was stripped into digits and fractions truncated | Reuse strict Money parsing with explicit locale inference | Reject malformed amounts rather than silently changing them |
| CSV duplicates | Each row rescanned the full existing ledger and duplicates inside the same file were missed | Hash-based normalized duplicate keys; deterministic category matching and guarded column indexes | Expected linear duplicate-detection work and safer import previews |
| CSV resource use | Unbounded file/row ingestion and stale default category after book changes | 10 MiB / 10,000-row input limits and destination-category reset | Bound import work and avoid using a previous book's category |
| Lock | Multiple inactive/background events reset the grace-period start | Preserve the earliest suspension | Prevent unintended extension of the unlock grace period |
| Tooling | Motion scripts and screenshots used unrelated absolute directories and broad process killing | Project-local outputs, XCTest attachments, per-process recorder cleanup | Reproducible verification without touching unrelated project files |
| Release | IPA destination was hard-coded | Optional IPA_DELIVERY_DIR override; publish staging inside project | Honor the current project-only instruction while preserving the usual default |

## Verification

- Final unit run: **83 tests passed**, zero failures (`build/audit/final-regressions.xcresult`).
- Complete UI run: 37 scenarios executed; 35 passed and two exposed stale test references (context-menu capitalization and a toolbar button removed in the existing UI).
- Updated those tests to follow the current UI without weakening their outcome assertions. Final targeted run: **6 UI tests passed**, covering both corrected scenarios, card reordering, CSV navigation, cancelled/committed pull dismissal, and rapid open/close reversal. Every one of the 37 UI scenarios has a passing result across the complete run and targeted reruns. The entire suite was not redundantly rerun after the final focused changes.
- Release device build succeeded without compiler warnings. ZIP integrity and SHA-256 checks passed; delivery copies match their source packages.
- Shell syntax checks passed. Frame-extractor invalid-FPS input fails promptly instead of crashing or looping.
- Captured home and entry screenshots were visually inspected. An additional final three-card open/close test passed (`build/motion/capture.PZnYKq/Motion.xcresult`); all three retained detail screenshots were inspected. The simulator video recorder reported an existing host recording on both attempts, so no new motion video was captured. The capture script now detects recorder startup failure, and frame extraction reports missing/unreadable input without an unhandled exception. No physical-device frame-time or leak measurements are claimed.
- Logs, xcresults, screenshots, and packages are retained under `build/audit`, `build/motion`, and `build/packages`.

## Limits and remaining engineering work

This audit does not establish that the app is universally bug-free or leak-free. Physical-device Instruments allocations, energy, thermal behavior, frame pacing, notification delivery, Face ID prompts, and installation through SideStore require device validation. Simulator interaction tests establish functional outcomes, not a measured 120 Hz frame-time guarantee.

Core Data still runs on the main actor and retains complete value snapshots. Transaction batching and lazy rendering reduce costs, but very large ledgers will eventually need background import/persistence, pagination, and cached analytics snapshots. Analytics and card-back metrics still contain repeated derived calculations. Integer aggregates remain Int64-based; pathological datasets near the per-entry numeric maximum need a separately specified aggregate-range policy. Large-scale architecture changes and a new numeric contract were not mixed into this UI-preserving release.

Bill reconciliation happens when the application runs/reloads. It is not an iOS background execution guarantee. Notification delivery remains subject to system permission and scheduling limits.
